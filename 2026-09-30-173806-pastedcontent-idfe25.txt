  The existing unit tests pass (14 of 14); they don't exercise the browser.

  Two things failed along the way and shaped the final setup:
  - Proxy blocked by Obscura: with --proxy socks5://prts-vpn:1080 alone, every
    navigation failed with a network error. Obscura's private-network guard
    blocks the proxy itself because it sits on a private Docker address, so the
    service runs with --allow-private-network.
  - PDF request bypassed the proxy: context.request.get runs in the Playwright
    driver inside pipbot, not in the browser. Over CDP it inherits neither the
    launch proxy nor the user agent, so IEEE returned a WAF challenge page
    instead of the PDF. This is why fetch_pdf needed one line beyond the launch
    swap.

  Files changed

  - bot/browser.py (new): three helpers.
    - get_browser() reads BROWSER_BACKEND, OBSCURA_CDP_URL and
      OBSCURA_CDP_TOKEN, connects with connect_over_cdp, and falls back to
      chromium.launch() with the original options after a warning.
    - get_context() reuses browser.contexts[0] if present, otherwise creates a
      new context.
    - get_request() returns context.request on Chromium; on Obscura it builds a
      request client with the proxy, user agent and the context's cookies.
  - bot/modules/ieee.py: fetch_pdf() uses the three helpers. The page
    navigation, PDF URL, headers, timeouts and validation are untouched.
  - compose.yaml: new obscura service.
    - Flags: --stealth, --proxy (from IEEE_SOCKS_PROXY, same default as the bot)
      and --allow-private-network.
    - Environment: OBSCURA_SCRIPT_DEADLINE_MS=60000 and a required
      OBSCURA_CDP_TOKEN.
    - Networking: on the default and ieee-proxy networks, with no port published
      to the host.
    - pipbot gets OBSCURA_CDP_URL=ws://obscura:9222 and depends_on: obscura.
  - .env.example: documents BROWSER_BACKEND and OBSCURA_CDP_TOKEN.
  - README.md: new "Browser backend (Obscura)" section with the obscura serve
    command and why each flag is needed.
  - .env (untracked): I appended a generated OBSCURA_CDP_TOKEN, because Obscura
    refuses to listen beyond loopback without one. Compose now errors if it is
    missing.

  The Dockerfile is unchanged, so bundled Chromium stays installed for the
  fallback.

  Things to know

  - The browser adds little here: in my tests IEEE served the PDF to a request
    with just the campus proxy and the browser user agent, no cookies. I left
    the flow as it was since you asked not to change scraping logic.
  - User agent differs under Obscura: the custom user agent only applies on the
    Chromium path; the reused default context presents Obscura's own stealth
    identity (Windows Chrome 143). The PDF request still sends the original one.
  - --allow-private-network loosens Obscura's SSRF guard: pages it loads could
    reach internal addresses. The bot only navigates to ieeexplore.ieee.org, and
    the port isn't published, so the exposure is small.
